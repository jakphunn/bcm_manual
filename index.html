🛠️ ขั้นตอนก่อน Deploy

คู่มือสำหรับผู้ที่ clone โปรเจกต์ BCM Operation App ไปใช้งานบนบัญชี Google Apps Script ของตนเอง

ภาพรวมสั้น ๆ: โปรเจกต์นี้เป็น Google Apps Script (GAS) Web App ที่ใช้ Google Spreadsheet เป็นฐานข้อมูล เมื่อ clone มาแล้ว คุณต้อง สร้างโปรเจกต์ Apps Script ของคุณเอง แล้ว รันฟังก์ชันตั้งค่า 2 ตัว ก่อน deploy ฐานข้อมูลและไฟล์รูปจะถูกสร้างอัตโนมัติบน Google Drive ของคุณ ไม่ต้องแก้โค้ด
สารบัญ
  1. สิ่งที่ต้องเตรียม (Prerequisites)
  2. ขั้นตอนติดตั้ง (Clone → Push → Setup → Deploy)
  3. ฟังก์ชันที่ต้องรันก่อน deploy (สำคัญ)
  4. Script Properties & การตั้งค่าเสริม (LINE)
  5. บัญชีผู้ใช้เริ่มต้น & สิ่งที่ต้องเปลี่ยน
  6. เช็คลิสต์ก่อน deploy

1. สิ่งที่ต้องเตรียม (Prerequisites)

  • Node.js — ตรวจสอบด้วย node -v
  • clasp (เครื่องมือ sync โค้ด ↔ Apps Script) — ติดตั้ง: npm install -g @google/clasp แล้วตรวจสอบ clasp --version
  • บัญชี Google ที่จะเป็นเจ้าของแอป และ เปิดใช้ Apps Script API ที่ script.google.com/home/usersettings (เปิดสวิตช์ "Google Apps Script API")
  • git สำหรับ clone โปรเจกต์

2. ขั้นตอนติดตั้ง

1 Clone โปรเจกต์

git clone <URL ของ repo>
cd bcm-operation-app

2 Login clasp ด้วยบัญชี Google ของคุณ

clasp login

เบราว์เซอร์จะเปิดให้ยืนยันตัวตน เมื่อสำเร็จจะขึ้น Authorization successful.

3 สร้างโปรเจกต์ Apps Script ของคุณเอง

⚠️ สำคัญมาก: ไฟล์ .clasp.json ที่ติดมากับ repo มี scriptId ของ เจ้าของเดิม ซึ่งคุณ ไม่มีสิทธิ์เข้าถึง — ต้องสร้างของตัวเองก่อน มิฉะนั้น clasp push จะ error

ลบ .clasp.json เดิมทิ้ง แล้วสร้างใหม่:

# macOS / Linux
rm .clasp.json
clasp create --title "BCM Operation App" --rootDir .
  • ถ้าถามประเภทโปรเจกต์ ให้เลือก standalone
  • คำสั่งนี้จะเขียน .clasp.json ใหม่พร้อม scriptId ของคุณ

4 Push โค้ดขึ้น Apps Script

clasp push

จะอัปโหลดไฟล์ .gs, .html และ appsscript.json (ไฟล์ .md และคู่มือนี้ถูกข้ามด้วย .claspignore)

Drive Advanced Service: appsscript.json เปิดบริการ Drive v2 ไว้แล้ว (ใช้แปลงไฟล์ Excel ตอนอัปโหลดแบบฟอร์ม) จึงถูกตั้งค่าให้อัตโนมัติเมื่อ push — ไม่ต้องเปิดเองในเมนู

5 เปิด Editor แล้วรันฟังก์ชันตั้งค่า

clasp open

ดูรายละเอียดฟังก์ชันที่ต้องรันใน หัวข้อที่ 3 ด้านล่าง (รัน setupSampleSheets() แล้วตามด้วย installTriggers())

ครั้งแรกจะมีหน้าจอขออนุญาต (OAuth): เนื่องจากแอปยังไม่ผ่านการตรวจสอบของ Google จะขึ้น "Google hasn't verified this app" → กด Advanced → Go to BCM Operation App (unsafe) → Allow ซึ่งเป็นเรื่องปกติสำหรับสคริปต์ของคุณเอง

6 Deploy เป็น Web App

วิธีที่ A — ทดสอบเร็ว (ไม่สร้าง deployment): Editor → Deploy ▾ → Test deployments → Web app → คัดลอก URL

วิธีที่ B — Deploy จริง:

clasp deploy --description "production"

แล้วเข้า Editor → Deploy → Manage deployments เพื่อเอา Web app URL

การตั้งค่า deploy ถูกกำหนดไว้ใน appsscript.json แล้ว: Execute as: User deploying (คุณ) และ Who has access: Anyone

3. ฟังก์ชันที่ต้องรันก่อน deploy สำคัญ

เปิด Apps Script Editor → เลือกชื่อฟังก์ชันจาก dropdown ด้านบน → กด Run ตามลำดับนี้:

ลำดับฟังก์ชันอยู่ในไฟล์ทำอะไร
1️⃣ setupSampleSheets() server/Setup.gs สร้าง Google Spreadsheet ฐานข้อมูลใหม่บน Drive ของคุณ, สร้าง 9 แท็บ (Employees, Stores, Tasks ฯลฯ), ใส่ข้อมูลตัวอย่าง และ บันทึก SPREADSHEET_ID ลง Script Properties ให้อัตโนมัติ
รันซ้ำได้ปลอดภัย — จะไม่ทับข้อมูลที่มีอยู่
2️⃣ installTriggers() server/Triggers.gs ติดตั้ง trigger ตามเวลา 3 ตัว (timezone Asia/Bangkok): dailyReminder (~06:00 แจ้งเตือน CM), checkDelayedTasks (~00:30 ตรวจงานล่าช้า), cleanupOldData (~01:00 ลบข้อมูลเก่ากว่า 30 วัน)
รันซ้ำได้ปลอดภัย — จะลบ trigger เดิมก่อนเสมอ ไม่ซ้ำซ้อน
✅ ตรวจผล setupSampleSheets(): ดู Execution log (เมนู View → Logs) จะพิมพ์ลิงก์ Spreadsheet เปิดดูควรมี 9 แท็บ และแท็บ Employees มี 4 แถว (admin01, vp01, dm01, cm01)
✅ ตรวจผล installTriggers(): log พิมพ์ Triggers installed. และดูได้ที่แถบ Triggers (ไอคอนนาฬิกา) ด้านซ้าย จะเห็น trigger 3 ตัว
📁 โฟลเดอร์รูปภาพ: ไม่ต้องสร้างเอง — โฟลเดอร์ Drive สำหรับเก็บรูป check-in (PHOTO_FOLDER_ID) จะถูกสร้างและบันทึกอัตโนมัติเมื่อมีการ check-in พร้อมรูปครั้งแรก

4. Script Properties & การตั้งค่าเสริม

ค่าลับ (secrets) ไม่ได้เก็บในโค้ด แต่เก็บใน Script Properties (Editor → ⚙ Project Settings → Script Properties)

Keyจำเป็น?ตั้งค่าอย่างไร
SPREADSHEET_ID อัตโนมัติ ถูกตั้งให้เองโดย setupSampleSheets() — ไม่ต้องทำมือ
PHOTO_FOLDER_ID อัตโนมัติ ถูกตั้งให้เองเมื่อ check-in พร้อมรูปครั้งแรก — ไม่ต้องทำมือ
LINE_CHANNEL_TOKEN เสริม ใส่เองเมื่ออยากเปิดแจ้งเตือนผ่าน LINE OA (ดูด้านล่าง)

การเปิดแจ้งเตือน LINE OA (ถ้าต้องการ)

ระบบส่งอีเมลได้ทันทีโดยไม่ต้องตั้งค่าอะไรเพิ่ม ส่วน LINE เป็น ตัวเลือกเสริม:

  1. สร้าง LINE Official Account + Messaging API channel ที่ LINE Developers
  2. คัดลอก Channel access token มาใส่ใน Script Properties คีย์ LINE_CHANNEL_TOKEN
  3. ใส่ line_user_id ของพนักงานแต่ละคนในแท็บ Employees (หรือให้ผู้ใช้ผูกบัญชีเองผ่านเมนู LINE)
  4. ตั้ง Webhook URL ของ LINE channel = Web app URL ที่ deploy ได้ (สำหรับการผูกบัญชีอัตโนมัติ)
สวิตช์ CONFIG.NOTIFY.LINE_ENABLED ใน server/Config.gs เปิดอยู่แล้ว (true) แต่ระบบจะ ไม่ส่ง LINE จนกว่าจะมี token + line_user_id ครบ — ถ้าไม่ตั้ง ก็ใช้แค่อีเมลได้ตามปกติ

5. บัญชีผู้ใช้เริ่มต้น & สิ่งที่ต้องเปลี่ยน

หลังรัน setupSampleSheets() จะมีบัญชีตัวอย่าง 4 บัญชี รหัสผ่านเริ่มต้นเหมือนกันหมดคือ changeme123:

Employee IDตำแหน่งรหัสผ่านเริ่มต้น
admin01adminchangeme123
vp01vice presidentchangeme123
dm01district managerchangeme123
cm01cluster managerchangeme123
⚠️ ก่อนใช้งานจริง ต้อง:
  • เปลี่ยนรหัสผ่านทุกบัญชี (รหัสผ่านเก็บเป็น plaintext ในแท็บ Employees ตามดีไซน์ — admin แก้ในชีตได้โดยตรง หรือผ่านเมนู "จัดการฐานข้อมูล")
  • ลบ/แก้ข้อมูลตัวอย่าง (ร้าน, งาน) แล้วใส่ข้อมูลจริงขององค์กร โดยเฉพาะ พิกัด latitude/longitude ของร้าน ที่ใช้ตรวจ GPS ตอน check-in
  • อัปโหลดแบบฟอร์มตรวจร้าน (.xlsx) จริงผ่านเมนู "อัปโหลดแบบฟอร์ม"
